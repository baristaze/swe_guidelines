# Architecture review

**Scope.** `.`: the whole working tree of `free-journalism` (branch `master`, no commits, every file untracked), read from the working tree; arch-check v0.37.0 run once for all groups: 106 rules, 0 findings, 3 exceptions applied (ASY-16 under ADR-0007, NET-09 ×2 under ADR-0009).
**Groups.** om, contracts, context, storage, async, network, delivery, ops
**Lenses.** 248 applied, 189 passed, 57 findings, 2 unverified, 10 not applicable

## Findings

- **DEL-51 high** `.github/workflows/deploy-production.yml:512` The production smoke job takes on the production deploy role (the apply credential) and then runs `uv sync --all-packages`, so a dependency install runs while that credential is held. Fix: split the job so that no install or build runs in any job that holds the deploy role, and let the smoke test use a narrow credential.
- **DEL-51 high** `.github/workflows/deploy-staging.yml:312` The staging smoke job takes on the AdministratorAccess deploy role (lines 263-268) and then runs `uv sync --all-packages`. Fix: run the install and the telemetry test in a job with only a narrow read/smoke credential, and mint the smoke token in a separate job that installs nothing.
- **DEL-49, DEL-27 high** `apps/portal/src/main.tsx:18` `Sentry.init` has no `beforeSend` scrubber, so nothing removes the authorization header, cookies or credential fields before an event leaves the tab. The events also carry no service tag and no request id. Fix: pass a `beforeSend` that scrubs the same headers and fields as `SCRUBBED_HEADERS`/`SCRUBBED_FIELDS` in `infra/src/acme/infra/observability.py`.
- **OPS-28 high** `deployment/terraform/bootstrap/staging/main.tf:18` The push-only `build` role and the `deploy` role (line 19) both trust the `staging` environment on `main` with the same OIDC subject. The `build-portal` job, which runs `pnpm install` with `id-token: write`, can therefore assume the AdministratorAccess deploy role. Fix: give the build credential its own repository-host environment (for example `staging-build`) and name it in the build role's trust.
- **ASY-24 high** `integrations/src/acme/integrations/email/postmark.py:54` The notifier's only external effect is keyed only through Postmark `Metadata`, which Postmark does not deduplicate. A replayed or requeued SEND_NOTIFICATION item (`workers/notifier/src/acme/workers/notifier/handler.py:63-72`) therefore sends every address again. Fix: key the send where the provider dedupes (Resend's `Idempotency-Key`), or record a per-address sent marker under the item's key before sending and reconcile against it.
- **CTX-11, CTX-10 high** `om/src/acme/om/idempotency/storage/impl/postgres.py:98` `holds_attempt` reads a user-scoped marker by `org_id` and id with no `user_id` in its `WHERE`. Its interface (`om/src/acme/om/idempotency/storage/__init__.py:26`) takes only the tenant. Fix: change the signature to `(org_id, user_id, marker_id, attempt_token)` and filter on `user_id`, as `finish`, `release` and `read_marker` already do.
- **ASY-14, STO-22 high** `om/src/acme/om/support/impl/manager.py:146` `settle_checkout` checks `PENDING` by reading, then upserts the pledge with no `version` compare-and-set, and lands its two outbox rows under fresh `new_id()` keys. Two concurrent redeliveries both settle and enqueue two SUPPORT_RECEIPT items, and `cancel_pledge`/`attach_checkout` (line 108) can overwrite a settlement last-writer-wins. Fix: write the settlement by compare-and-set on the pledge's status or version (give `Pledge` a `version`), and derive both outbox row ids from `delivery_key` (UUID v5) so a redelivery collides.
- **STO-20 high** `om/src/acme/om/support/impl/manager.py:155` `settle_checkout` commits the pledge's core write (line 152), then hands off to the `activity` role with a second storage call, `append_contribution`, instead of an outbox row in the same atomic write. Only a provider redelivery repairs a crash between the two. ADR-0010 does not quote the rule and is not cited at the code. Fix: land a work row with the settlement's `outbox_rows` and have its handler append the contribution, or record an ADR that quotes STO-20 and cite it beside the call.
- **CTX-18 high** `om/src/acme/om/tenancy/impl/manager.py:441` `authenticate_login` accepts an operator token (`fjo_`), and `exchange` (line 658) never refuses `CredentialKind.OPERATOR_TOKEN`. An operator token can therefore be traded on `/v1/auth/exchange` for a tenant session in any tenant its identity belongs to. Fix: accept only the login and tenant-session prefixes on the exchange and memberships routes, or have `exchange` refuse an operator token by kind.
- **CTX-37 high** `om/src/acme/om/tenancy/impl/manager.py:482` `redeem_socket_ticket` builds the socket's `OpContext` from the issuer's current membership role. An API-key ticket therefore gets the issuer's full role rather than the lower of the key's role and the issuer's, and `recheck_session` (line 766) never re-caps it. Fix: for an API-key ticket, set the role to `rules.lower_role(key.role, membership.role)` and recheck that capped role on every recheck.
- **CTX-27, CON-17 high** `om/src/acme/om/tenancy/impl/manager.py:898` `revoke_api_key`, and `remove_member` when it revokes the member's keys (line 853), publish no `SESSION_REVOKED`, so a socket opened from a key's ticket stays open until its next recheck. `revoke_api_key` also returns `None` instead of the revoked key. Fix: publish `SESSION_REVOKED` for each revoked key id, the same way ended sessions are announced.
- **OPS-05 high** `om/src/acme/om/tenancy/impl/manager.py:931` `GET /v1/admin/orgs` (`services/api/src/acme/services/api/routers/admin.py:38`) lists every live tenant with no tenant parameter. - **CTX-11 high** `om/src/acme/om/tenancy/storage/impl/postgres.py:342` The marker guard in `remint_api_key` checks `IdempotencyMarkers` by tenant, id and token, but not by the user the marker belongs to. Fix: add `IdempotencyMarkers.user_id == issued_by` to the `exists()` guard.
