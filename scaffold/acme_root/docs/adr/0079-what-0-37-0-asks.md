# ADR 0079: What guideline 0.37.0 asks

**Status**: accepted (2026-09-26).

## Context

Acme moves its pin from guideline v0.36.0 to v0.37.0. The release makes
the guideline's templates and scaffolds say what its text says. It
reverses one rule: a work row is done once its item is queued. Here is
where Acme stands on each rule the release changes:

| Rule | What v0.37.0 asks | Here |
|------|-------------------|------|
| STO-20, Database Roles | An entity change's row is done once its event is appended and the bus took its publish. A work row is done once its item is queued: its `WORK_AVAILABLE` wake-up is a hint, and a worker's poll stands in for it. | Follows. The relay marks a `work.<kind>` row done once `enqueue_relayed` has landed the item, whatever became of the wake-up ([ADR 0062](0062-a-dropped-publish-leaves-its-outbox-row-pending.md)). [ADR 0067](0067-what-0-36-0-asks-and-what-stays-a-choice.md) recorded this as a deviation from v0.36.0. It is the rule now. |
| ASY-25, The Work Queue | An enqueue publishes `WORK_AVAILABLE` only when its insert won. A worker also polls the queue, on an interval from its settings, so a dropped wake-up costs an item one poll interval at most. | Follows. The work manager publishes only on `InsertOutcome.INSERTED`, so a retried enqueue and a second relay of a row publish nothing. The loop claims on the wake-up or every `worker_poll_seconds` (`ACME_WORKER_POLL_SECONDS`, 5 by default), whichever comes first. A test now holds the poll: an item whose wake-up the bus dropped is claimed on the next poll. |
| CTX-03, OpContext; OM-15, Pure Rules | The role-to-permission table lives in the tenancy namespace's rules module, `rules.py`. A table a decision reads is a rule like any other. | Follows with this change. The table moves from `tenancy/types/role.py` to `tenancy/rules.py`, with everything beside it: the operator plane's table, the ladder of the person roles, and their lookups. `types/role.py` is gone. |
| OPS-11, Operational Skills | An audit opens with the role the section's table gives it: none for `audit-query-indexes`, `audit-database-calls`, and the two optional audits, and investigator for `audit-retention` and `audit-deploy-time`. An audit of calls ranks its fixes: remove, fold, defer, cache, and only then parallel. | Follows. Each audit's "Role and credential" section opens with that role, and `ops/README.md` gives each the same, which `infra/tests/test_ops_skills.py` holds. `audit-database-calls` and `audit-provider-calls` rank their fixes in that order. |

The rest of the release changes the templates and the scaffolds only.
`ops-investigate`, `ops-watch`, and `stress-test-run` read the queue's
gauges only where there is a worker. Acme has one, and its skills are
its own texts, fuller than the templates.

`make check` runs `arch-check` at v0.37.0, and it passes: 106 rules over
352 files, 5 findings accepted by an exception. The checker of v0.37.0
is the checker of v0.36.0 with a new version number, so it finds the
same.

## Decision

**The role table is a rule, so it lives with the rules.** The tenancy
rules module already held the cap, `role_at_most` and `capped_role`, and
read the ladder from the types to apply it. Now the table, the ladder
the table holds, and the cap sit in one module. The values and the
lookups are the same. Every import follows, and no module keeps a copy.

**The work namespace's maps stay beside its types.** OM-15 names "a
table a decision reads declared beside the types". `WORK_PAYLOADS` and
`ORCHESTRATION_INPUTS` fix the shape of a payload, as `TOPIC_PAYLOADS`
does, and the guideline's worker scaffold puts `WORK_PAYLOADS` in the
types. `WORK_ENQUEUE_PERMISSIONS` is read by no decision: only the test
that holds each kind's permission to its handler's calls reads it.

**Nothing of v0.37.0 is a deviation.** The two other decisions of ADR
0067 stand: the optional audits also count, and the socket's recheck
setting has a name of its own. v0.37.0 does not change the text they
depart from.

## Consequences

- ADR 0062 follows the guideline for a work row as it does for an
  entity change. ADR 0067's row in the deviations table keeps its other
  two decisions.
- The relay cites ADR 0062 where it marks a work row done.
- A new table that a tenancy decision reads goes in `tenancy/rules.py`.
